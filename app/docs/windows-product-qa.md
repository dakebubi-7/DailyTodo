# DailyTodo Windows Product QA

Use this checklist for a clean Windows machine or virtual machine. Record the
Windows version, display scale, installer artifact name, source commit, and
result for each failed item. These checks are manual pending until performed on
an actual clean machine.

## Test Setup

- [ ] Start from a Windows user profile without a previous DailyTodo install.
- [ ] Disconnect or disable any configured AI credentials unless the scenario
      explicitly requires them.
- [ ] Have a small backup artifact available for restore testing.
- [ ] Use the NSIS installer generated by `npm run electron:build`, not a
      development-server build.

## Install And Launch

- [ ] Run the NSIS installer and confirm the selected installation directory is
      honored.
- [ ] Confirm DailyTodo is available from the Start Menu.
- [ ] Launch DailyTodo from the Start Menu and verify the main task workspace
      opens.
- [ ] When the installed build provides a desktop shortcut, launch from it and
      confirm it opens the same application instance.
- [ ] Launch DailyTodo a second time and confirm the existing instance is
      focused rather than creating an independent second task store.
- [ ] Confirm the installed executable is not dependent on the development
      checkout, a personal drive path, or local environment overrides.

## Window, Tray, And Display Recovery

- [ ] Click minimize and confirm the window hides to the system tray. It must
      not exit.
- [ ] Close the main window with the default setting and confirm it hides to
      the system tray.
- [ ] Restore the application from the tray and confirm the task workspace is
      usable.
- [ ] Use the tray's explicit Quit command and confirm the process exits.
- [ ] Enable the advanced close-to-exit setting, reopen the app, close the main
      window, and confirm it exits. Minimize must still hide to tray.
- [ ] Restore the default close behavior after the check.
- [ ] Move the app to a secondary display, close it to tray, disconnect or
      change the display arrangement, then restore it. Confirm the window is
      visible and usable on an available display.
- [ ] Check normal task-list layout at 100%, 125%, 150%, and 200% Windows
      display scaling. Titles, controls, and dialogs must remain reachable.

## Local Data, Backup, And Support

- [ ] Create several tasks, a partial completion review with a blocker, and a
      manual Today Focus selection. Restart the app and confirm they persist.
- [ ] Open the data/recovery/diagnostics locations from Settings and confirm
      each action opens an expected local folder without revealing credentials.
- [ ] Export a backup from Settings and verify a backup artifact is created.
- [ ] Inspect the backup only through its supported preview/restore flow and
      confirm it describes logical DailyTodo state rather than vault contents
      or API credentials.
- [ ] Start a restore, verify the preview and explicit confirmation appear, and
      cancel once. Confirm nothing changes.
- [ ] Restore a known backup, confirm a pre-restore recovery point is created,
      and confirm the app restarts as directed.
- [ ] After restart, verify restored tasks, history, settings, and Today Focus
      state are present.

## AI And Daily Execution

- [ ] With AI-assisted review disabled, confirm no AI-specific prompt,
      suggestion control, request, or automatic retry appears.
- [ ] Record a task as partial with a blocker and next step. Confirm it remains
      open after restart and ordinary carryover retains it appropriately.
- [ ] With AI unavailable or credentials absent, enable review only if needed
      for this scenario. Confirm the saved evidence remains visible, no task is
      changed automatically, and failure feedback is non-destructive.
- [ ] Confirm a manual Today Focus selection can be created, edited, canceled,
      and limited to three tasks without AI.

## Uninstall And Reinstall

- [ ] Exit DailyTodo with the tray Quit command before uninstalling.
- [ ] Run the NSIS uninstaller and record whether user data is retained or
      removed by the observed installer behavior.
- [ ] Reinstall the same build and verify the observed data behavior matches
      the recorded uninstall result.
- [ ] Reinstall over an existing installation and verify launch, tray behavior,
      backup access, and saved data behavior. Record any migration issue before
      approving a release.

## Result Record

- [ ] Document the machine/VM, Windows version, display scaling, installer
      SHA-256, source commit, tester, date, pass/fail result, and follow-up
      issue links in the release record.
