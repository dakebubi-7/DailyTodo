# DailyTodo 自动复盘与周/月报 — PRD（需求规格）

> 本文是 [[DailyTodo-自动复盘与周月报-设计]] 的工程化版本：把设计蓝图拆成可执行的功能模块，每条带**验收标准**和**优先级**，并给出里程碑。
> **范围**：需求规格，不含具体实现代码。
> **优先级定义**：**P0** = 最小可用闭环（MVP，必须有）；**P1** = 体验完整（应尽快做）；**P2** = 锦上添花（有余力再做）。

---

## 1. 目标与非目标

### 1.1 目标

- 用户每天写完任务后，应用自动生成「复盘 / 明日待办 / 可复用知识」并回填到当天日记。
- 自动生成个人周复盘、月报。
- 不同用户用不同模板都能工作；小白零配置即用。
- 关机/软件关闭不影响——下次上线自动补齐。

### 1.2 非目标（本期不做）

- 不做团队协作 / 多人共享。
- 不做云端账号体系（除非走 SaaS 代付，见 M8，默认延后）。
- 不替用户决定内容质量——AI 产出是草稿，用户负责把关。

### 1.3 成功判据（一句话）

> 一个新用户装完应用、什么都不配，连续用三天（中间关机一次），第四天打开 Obsidian，能看到这四天每天都有自动生成的、结构正确的复盘。

---

## 2. 用户与场景

| 用户类型 | 特征 | 关键诉求 |
|---------|------|---------|
| 本人（开发者） | 懂底层，自定义需求强 | 完全可配、可改 prompt |
| 小白用户 | 只会用 UI，不想学 | 装完即用，用自己模板也能跑 |
| 工作人 | 要交周报/月报 | 公司模板、脱敏、正式语气、量化数字 |

---

## 3. 功能模块与验收标准

### M1 — 回填引擎核心（P0）

**描述**：一个通用脚本/模块，读 daily 文件 + 配置，把生成内容按标记回填。

**需求**：
- 段落用 `<!-- DAILYTODO:<KEY>:START/END -->` 标记界定。
- 只替换 START/END 之间内容，不动其他段落。
- 配置区分 `type: ai` 与 `type: deterministic`。
- AI 写入段落必须带状态元数据：`AI_HASH`（基于实际正文计算）与 `🤖 AI 草稿` 标识。
- 支持显式冻结标签（如 `<!-- DAILYTODO:FREEZE -->` 或配置等价状态），冻结后任何自动任务都不得覆盖。

**验收标准**：
- [ ] 给定一个带标记的 daily 文件和配置，脚本能精确替换指定标记区间。
- [ ] 重复运行两次，文件内容一致（**幂等**）。
- [ ] 应用自己写的「工作/灵感/任务」段落在回填后**字节不变**。
- [ ] 标记是 HTML 注释，Obsidian 预览模式下不可见。
- [ ] 利用 diff 算法或字节流比对，确保除 START/END 标记内部区间外，文件其余部分的原始 Markdown 语法、特殊字符（如 YAML Frontmatter、Obsidian 内部链接 `[[...]]`）在回填后完全不发生变异或失效。

---

### M2 — 日复盘 AI 生成（P0）

**描述**：调 LLM 生成「复盘 / 可复用知识 / 建议性待办」。

**需求**：
- 输入 = 当天已完成任务 + 工作记录 + 灵感闪念。
- LLM 走 **OpenAI 兼容接口**：`base_url + api_key + model` 全读环境变量/配置。
- 「明日待办」= 应用确定性结转未完成任务 + AI 追加建议。
- 量化数字由程序统计，不让 AI 编。

**验收标准**：
- [ ] 配好 key 后，对一个真实 daily 文件能生成三段非空、相关的内容。
- [ ] 切换 `base_url/model`（如 DeepSeek↔本地模型）无需改代码。
- [ ] key 缺失/网络失败时**不破坏文件**，并给出明确错误提示。
- [ ] AI 生成段落带可识别标记（如 `🤖 AI 草稿`、`confidence: low`）与 `AI_HASH` 状态指纹，与手写区分。

---

### M3 — 触发与健壮性（P0 核心 / P1 兜底）

**M3.1 应用调脚本（P0）**
- 应用同步完 daily 文件后，subprocess 调回填脚本。
- **验收**：用户在应用里点同步 → 几秒内当天复盘出现。

**M3.2 补偿扫描（P0）**
- 脚本运行时往回扫最近 N 天，对“未处理”或“可安全更新”的复盘段补生成。
- 废除模糊“判空”概念，采用 **状态指纹（Hash）+ 显式冻结标签** 判定：
  1. START/END 之间没有任何内容（或只有空行）→ `Unprocessed`，执行补全。
  2. 包含 `AI_HASH` → 重新计算“去掉 Hash 行后的实际正文 Hash”。若一致，说明用户未改动旧 AI 草稿，视为 `AI_Unmodified`，允许覆盖/更新；若不一致，说明用户微调过，视为 `User_Modified`，跳过且绝不覆盖。
  3. 没有 `AI_HASH` 且有内容 → 视为用户纯手写，跳过且绝不覆盖。
  4. 存在显式冻结标签（如 `<!-- DAILYTODO:FREEZE -->`）→ 无条件跳过，除非用户通过 UI/命令显式解冻。
- 强制重新生成必须是显式动作（如“重新生成本段”按钮/命令），不得由补偿扫描隐式触发。
- **验收**：
  - [ ] 删掉昨天的复盘内容后跑一次，昨天被补上。
  - [ ] 连续 3 天没跑，第 4 天跑一次，3 天全部补齐。
  - [ ] 用户手写了半段复盘的那天，补偿扫描**跳过、不覆盖**。
  - [ ] 用户只修改 AI 草稿中的一个错别字后，下一次补偿扫描识别为 `User_Modified` 并跳过。
  - [ ] 未被用户修改过、Hash 一致的旧 AI 草稿允许被显式更新策略覆盖。
  - [ ] 带冻结标签的段落在补偿扫描和批量生成中都不会被覆盖。

**M3.3 定时器 + 开机自启（P1 兜底）**
- 应用开机自启；启动时先跑补偿扫描。
- 可选系统定时任务（Windows 任务计划程序，含"错过后尽快运行"）。
- **验收**：模拟"晚上关机错过定时"→ 次日开机后内容自动补齐。

---

### M4 — 个人周复盘（P1）

**描述**：聚合本周 daily + 日复盘，生成周复盘。

**需求**：
- 输入 = 本周 7 个 daily + 各日复盘。
- 输出 = `logs/weekly-review/YYYY-Wxx.md`。
- 模板参考现有 2026-W21 周知识复盘结构。
- 触发：每周日定时 / 手动命令。

**验收标准**：
- [ ] 对一个有 ≥3 天记录的周，生成结构完整的周复盘（概览/关键事件/知识增量/未完成/下周计划）。
- [ ] 数字统计（完成任务数、活跃天数）由程序算，准确。
- [ ] 缺失某天 daily 时不报错，按已有数据生成。

---

### M5 — 月报（P2）

**描述**：聚合当月 daily + 周复盘，生成月报。

**需求**：
- 输出 = `logs/monthly-review/YYYY-MM.md`（个人月报；**需新建目录**）。
- 触发：每月底定时 / 手动。

**验收标准**：
- [ ] 能生成当月汇总（含 4 周复盘要点聚合）。
- [ ] 引擎与周复盘共用，仅时间窗/输入源不同。

---

### M6 — 模板适配（P1 / P2）

**M6.1 配置驱动（P1）**
- 引擎不硬编码段落名，全读配置。
- **验收**：换一份"整理未完成/明日要完成/下一步/今日总结"的配置，引擎无需改代码即可工作。

**M6.2 AI 认模板（P1）**
- 用户粘贴/保留自己模板 → LLM 识别段落语义 → 大白话确认 → 背后埋标记 + 生成配置。
- **验收**：给一个陌生的中文/英文模板，AI 能正确识别 ≥80% 段落角色，并生成可用配置。

**M6.3 模糊匹配 + 优雅降级（P2）**
- 内置近义词词典自动猜段落角色。
- 认不出时把内容追加文件末尾 + 纠正入口，**绝不报错/覆盖**。
- **验收**：给一个完全无法识别的模板，脚本不崩、不覆盖、有兜底输出。

---

### M7 — 产品化 UI（P1 / P2）

**M7.1 模板编辑器（P1）**
- 每段一行：显示开关、上下移、`[AI写/我自己写/搬任务]` 下拉、`[简短/适中/详细]` 旋钮。
- 背后自动生成 yaml + 埋标记，用户不见 yaml/标记。

**M7.2 首次向导（P1）**
- 选模板 → 设时间 → 选 AI，30 秒完成；可全程跳过用默认。

**M7.3 预设 + 覆盖（P2）**
- 预设 = base，用户改动存 override 层；支持「恢复默认」；预设升级时未改部分自动跟进。
- **验收**：改某段为"我自己写"后，其余段仍随预设升级；点"恢复默认"还原。

**通用验收**：
- [ ] 用户全程不接触 yaml / 标记 / 任务计划程序。
- [ ] 什么都不配也能正常生成（默认值装完即用）。

---

### M8 — 账号与登录（P2 / 未来，依商业模式而定）

**描述**：默认免登录、本地优先；登录仅在云同步/代付/团队场景才出现。

**需求**：
- 默认无账号，本地完整可用。
- 完全免登录状态下仅支持“用户自填 Key”模式（环境变量/本地配置文件），应用不提供匿名无限代付能力。
- 可选**本地密码锁**（防同台电脑他人翻看，不联网无账号）。
- 若做 SaaS 代付/免费额度：必须轻量登录（微信/GitHub/邮箱等）后换取带配额限制的 App-Token。
- 登录的目的仅是“给本地调用的云端 AI 算力账单做鉴权与配额控制”，不是读取或托管用户日记；日记仍保留在本地。

**验收标准**：
- [ ] 首次使用**不出现登录墙**。
- [ ] 关闭网络仍能完整使用核心功能（本地 key 模式）。
- [ ] 登录只作为“解锁云/代付功能”的入口出现。
- [ ] 未登录用户无法调用 SaaS 代付接口；登录用户请求必须绑定 App-Token、配额、速率限制与可撤销凭证。

---

### M9 — 对外工作周报/月报（P2）

**描述**：面向汇报的正式版本，区别于个人复盘。

**需求**：
- 可导入公司模板 → AI 认结构 → 用本周/本月数据填。
- **路径隔离**：对外产物不得写入个人 `logs/` 目录，必须输出到独立导出目录：`exports/weekly-reports/`、`exports/monthly-reports/`。
- **物理脱敏**：默认强制剔除所有包含 `tag: private`、`tag: secret` 或特定手写段落（如“灵感闪念”）的整段文本。
- 仅允许显式标记为 `type: work` 或等价工作白名单的内容进入 `exports/` 目录；即使 AI 脱敏失败，也由程序规则卡死底线。
- 正式语气；强提示“交前自己过一遍”。

**验收标准**：
- [ ] 导入一份公司周报模板，能按其字段生成草稿。
- [ ] 对外周报输出到 `exports/weekly-reports/`，对外月报输出到 `exports/monthly-reports/`，不与个人 `logs/` 复盘混放。
- [ ] 个人日记中的私人段落（读书/灵感）**不出现**在对外周报里。
- [ ] 含 `private` / `secret` 标签或未标记为 `type: work` 的内容不会进入 `exports/`。
- [ ] 输出明确标注“AI 草稿，需复核”。

## 4. 优先级汇总

| 优先级 | 模块 | 说明 |
|--------|------|------|
| **P0（MVP）** | M1 引擎核心、M2 日复盘生成、M3.1 应用调脚本、M3.2 补偿扫描 | 最小可用闭环：每天/补漏都能自动出复盘 |
| **P1** | M3.3 定时器兜底、M4 周复盘、M6.1 配置驱动、M6.2 AI 认模板、M7.1 模板编辑器、M7.2 首次向导 | 体验完整、可换模板、好上手 |
| **P2** | M5 月报、M6.3 模糊匹配/降级、M7.3 预设覆盖、M8 账号、M9 对外周报 | 锦上添花 / 依商业模式；对外产物必须走 `exports/` 隔离目录 |

## 6. 技术约束与依赖

- LLM 接口：OpenAI 兼容，凭证走环境变量/本地配置；SaaS 代付模式必须走登录后的 App-Token + 配额鉴权。
- 文件编码：UTF-8（vault 硬规则）。
- 跨平台路径：Windows / Unix 兼容（沿用 DailyTodo 已知挑战）。
- 写入安全：避免多窗口、后台补偿扫描、Obsidian、同步盘并发写坏同一文件。
- **原子化写入与文件锁（Atomic Write & File Lock）**：
  - 禁止直接 `open(file, 'w')` 覆盖原 Markdown 文件。
  - 标准流程：读取原文件 → 记录文件大小与修改时间 → 在系统临时目录生成临时文件并完成 START/END 替换 → 写入前再次检查原文件大小与修改时间 → 若期间文件被外部更改，放弃写入并报错/稍后重试 → 使用 OS 原子替换（如 Python `os.replace()`）瞬间覆盖。
  - 对同步盘（Syncthing/iCloud/Git/其他云盘）场景，批量补偿扫描必须降低冲突概率：单文件串行写、失败跳过、不做破坏性重试。
- **新建目录**：`logs/monthly-review/`（M5 个人月报时）、`exports/weekly-reports/` 与 `exports/monthly-reports/`（M9 对外汇报时）。

## 7. 风险与未决问题

| # | 风险/问题 | 现状 / 防御手段 |
|---|----------|----------------|
| 1 | “判空”误覆盖用户手写内容 | M3.2 已改为状态指纹 `AI_HASH` + 显式冻结标签；Hash 不一致或无 Hash 有内容均视为用户内容，跳过 |
| 2 | AI 认模板识别率不足 | M6.2 需保留人工确认 + 纠正入口兜底 |
| 3 | API 成本与小白门槛 | M2/M8：免登录仅自填 Key；SaaS 代付必须登录换 App-Token、配额与速率限制 |
| 4 | 量化数字准确性 | 一律程序统计，禁止 AI 生成数字 |
| 5 | 草稿质量参差 | 全程标注“AI 草稿”，把关责任归用户 |
| 6 | 同步盘/Obsidian/后台扫描并发导致冲突文件或覆盖新内容 | §6 强制原子写入、写前后 size/mtime 检查、外部更改时放弃写入、单文件串行处理 |
| 7 | 匿名 SaaS 免费额度被刷 | M8 明确未登录不能调用代付接口；登录后用 App-Token、配额、速率限制、可撤销凭证 |

## 8. Definition of Done（整体验收）

- [ ] §1.3 成功判据通过。
- [ ] P0 全部验收项打勾。
- [ ] 任何失败路径（无 key / 断网 / 认不出模板 / 关机错过）都**不破坏用户文件**。
- [ ] 用户全程不需要手动编辑 yaml、标记或系统定时任务。
- [ ] 对外产物（周报/月报）均标注"AI 草稿，需复核"。
