# 无感主题统一透明度设计

日期：2026-06-15

## 背景

用户在提高无感主题透明度后，主界面仍出现多块黑色/深色区域。根因是无感主题在 `app/src/styles/globals.css` 末尾存在多段覆盖样式，其中任务卡、日期卡、工具栏、输入区域等分别设置了独立深色背景。这些局部背景没有完全跟随统一透明度，导致截图中出现明显黑块。

## 目标

无感主题主界面改为统一透明玻璃效果：

- 主界面不再出现任务卡、日期栏、筛选栏、Tab、切换栏等局部黑色块。
- 主界面透明度以统一变量为准，视觉上像一整层玻璃。
- 保留必要文字、图标、细边线和轻微 hover/active 反馈。
- 每日任务编辑/输入框保持黑灰色，保证输入可读。
- 完成任务弹窗及其内部填写控件保持黑灰色，保证复盘填写可读。

## 非目标

- 不重做无感主题的整体配色体系。
- 不修改非无感主题。
- 不改变任务列表布局、拖拽、筛选逻辑或数据结构。
- 不移除设置面板、弹窗、菜单等需要强可读性的弹层底色。

## 方案

采用「统一玻璃 + 输入框例外」方案。

### 主界面统一玻璃

无感主题下，以下主界面容器取消独立深色底：

- `.date-card`
- `.date-stepper`
- `.daily-panel-switch`
- `.tabbar` 激活按钮
- `.task-toolbar`
- `.task-card`
- `.daily-work-preview`
- `.add-task`

这些区域统一改为透明或极淡玻璃，只保留细边线。hover 状态只使用极轻白色/灰色叠层，避免形成新的黑块。

### 黑灰输入框例外

以下控件保持黑灰底：

- 底部每日任务添加输入框 `.add-task-input`
- 任务行内编辑输入框 `.task-edit-input`
- 完成任务弹窗 `.completion-dialog`
- 完成任务弹窗内的 `.completion-field`
- 完成任务弹窗内的 `select`、`textarea`

黑灰输入框要求：

- 背景为半透明黑灰，而不是纯黑。
- 文字使用高对比浅色。
- placeholder 使用较低对比浅色。
- focus 状态只加轻微边框/光晕，不改变布局。

### 弹层可读性

设置面板、优先级弹层、月历弹层、标题栏菜单仍可保持较强底色，避免复杂壁纸影响可读性。完成任务弹窗明确属于保留黑灰底的可读性弹层。

## 预计改动文件

- `app/src/styles/globals.css`
  - 清理/覆盖无感主题末尾的局部黑色背景规则。
  - 增加无感主题主界面统一透明规则。
  - 增加无感主题输入框与完成弹窗黑灰例外规则。

如现有 verify 脚本需要适配选择器或断言，再改：

- `app/scripts/verify-frosted-glass-opacity-controls.ts`
- `app/scripts/verify-task-layout-unified-glass.ts`

## 验证计划

1. 运行透明度相关验证脚本，确认统一透明度变量仍生效。
2. 运行任务列表交互验证脚本，确认任务布局和交互未破坏。
3. 运行或截图检查无感主题：
   - 主界面没有任务卡、日期栏、筛选栏等大块黑色区域。
   - 每日任务添加输入框和行内编辑框仍是黑灰色。
   - 完成任务弹窗及内部输入区域仍是黑灰色且可读。

## 风险与处理

- 风险：过度透明会降低文字对比度。
  - 处理：主界面保留文字阴影/浅色文字和轻微边线；输入和完成弹窗保留黑灰底。
- 风险：旧的无感主题覆盖块很多，后续规则可能互相覆盖。
  - 处理：在文件末尾集中添加最终覆盖规则，避免散改导致优先级混乱。
- 风险：非无感主题被影响。
  - 处理：所有新增规则都限定在 `.theme-invisible` 范围内。
