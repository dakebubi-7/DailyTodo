## A1. 编辑能力抽成 Hook，推广到所有多行框

### 现状
`src/components/DailyWorkPanel.tsx` 内含约 120 行编辑器逻辑：自维护撤销/重做历史栈（含连续打字合并，COALESCE_MS=500）、程序化光标恢复、键盘处理（Tab/Shift+Tab 缩进、回车续列表、Ctrl+B/I、Ctrl+Z、Ctrl+Shift+Z / Ctrl+Y）、以及 `/` 命令菜单。这套能力**只在 `DailyWorkPanel` 一个组件内可用**。

其它多行 textarea 没有这些能力：
- `src/components/TaskCompletionDialog.tsx`（追加记录：今天情况 / 卡点 / 下一步）
- `src/components/TaskReviewDialog.tsx`（任务复盘）

纯函数编辑操作已在 `src/utils/markdownEditor.ts`（`indentSelection` / `outdentSelection` / `continueListOnEnter` / `wrapSelection`），可直接复用。

### 方案
新建 `src/hooks/useMarkdownEditor.ts`，把 `DailyWorkPanel` 中以下逻辑抽出为可复用 Hook：

- 撤销/重做历史栈（`historyRef` / `recordHistory` / `undo` / `redo` / `restoreSnapshot` / `resetHistory`）
- 程序化光标恢复 effect（`pendingSelectionRef` + setSelectionRange，**并入 A2 的滚动修复**）
- `handleTextareaKeyDown` 中的按键分发（Tab、回车续列表、Ctrl+B/I/Z/Y）

Hook 形态（接口示意，非最终签名）：

```
useMarkdownEditor({
  value,                 // 受控值
  onChange,              // 值变更回调
  textareaRef,           // 调用方持有的 ref
  command?: {            // 可选：/ 命令菜单。不传则禁用该功能
    items, open, index, onOpenChange, onIndexChange, onPick
  }
}) => {
  onKeyDown,             // 绑定到 textarea
  onChangeInternal,      // 绑定到 textarea onChange / onCompositionEnd
  // 历史与命令状态对外只读暴露需要的部分
}
```

### 接入范围（用户确认：仅多行框）
- DailyWorkPanel（重构为使用该 Hook，行为保持不变，含 `/` 命令菜单）
- TaskCompletionDialog 的多行字段（今天情况 / 卡点 / 下一步）——接入 Hook，**不传 command**
- TaskReviewDialog 的多行字段——同上
- 单行框（添加任务 `AddTaskInput`、搜索）**不接入**：Tab 仍用于切换焦点，`1.`/`1.1` 在单行无意义。

### 边界与注意
- 命令菜单（`/` 唤出任务列表）是 DailyWorkPanel 专属，作为 Hook 可选参数，其它框不传即关闭。
- 受控组件 + 程序化 `setDraft` 会清空浏览器原生 undo 栈，因此必须保留自维护历史栈。
- 中文输入法：保留 `isComposing` 判断与 `onCompositionEnd` 处理，避免拼字途中误触发续列表。

### 验收
- DailyWorkPanel 行为与重构前完全一致（Tab/编号/撤销重做/命令菜单/加粗斜体）。
- 在追加记录的三个多行字段中，Tab 缩进、回车续 `1.`/`1.1`、Ctrl+Z/Ctrl+Y 均可用。
- 单行框行为不变。

## A2. 修「回车要敲两下才上移」（随 A1 一起）

### 现状与根因
`src/components/DailyWorkPanel.tsx:143-151` 的 effect 在程序化续列表后只执行 `textarea.focus()` + `textarea.setSelectionRange(start, end)`，**未把光标滚动进可视区**。当新行落在可视区外，浏览器要等下一次真实输入事件才滚动，表现为"需要敲两下回车，文字才整体上移"。`globals.css` 中 `.daily-dialog-textarea` 的 `overscroll-behavior: contain` 可能进一步抑制自动滚动。

### 方案
在光标恢复 effect 设完 `setSelectionRange` 后，补一段**把光标行滚进可视区**的逻辑。textarea 无"滚动到光标"原生 API，采用按行号计算 scrollTop 的标准做法：

```
1. 取光标位置前的子串，统计换行数 → 当前行号 row
2. 估算行高 lineHeight（从 computed style 的 line-height 读取）
3. caretTop = row * lineHeight
4. 若 caretTop < scrollTop：scrollTop = caretTop（向上带回）
   若 caretTop + lineHeight > scrollTop + clientHeight：
     scrollTop = caretTop + lineHeight - clientHeight（向下带回）
```

此逻辑随 A1 一并落到 `useMarkdownEditor` 的光标恢复处，**一处修复、所有接入的多行框受益**。

### 验收
- 在编辑框底部连续按一次回车续列表，文字立即整体上移，光标始终可见，无需第二次回车。
- 普通换行（非列表）同样不再需要敲两下。

## A3. 日历完成度：让「已完成」明确可见

### 现状
- 完成度逻辑已存在：`DateNavigator.tsx:51-58` 的 `getDayStatus` 可算 `none / open / partial / done / urgent` 五态。
- 视觉只是日期格底部一个约 5px 小圆点（`globals.css:3441-3474`），存在感极低。
- `DateNavigator` 只收到任务列表，**没有每日 `已完成数/总数`**，无法显示"3/5"。
- `useTasks` 已能算当前选中日期的 `completedCount/totalCount`（`useTasks.ts:404-411`），但只用于顶部显示。

### 方案

1. **数据**：在 `useTasks` 中新增**按日期聚合的完成度表**：
   ```
   dailyCompletion: Record<string /* YYYY-MM-DD */, { done: number; total: number }>
   ```
   仅统计未 `cleared` 的任务，date 用 `getTaskDate(task, currentDate)`。通过 props 传给 `DateNavigator`。

2. **视觉**：日期格的小圆点改为**环形进度**（围绕日期数字的细圆环）：

   | 状态 | 环形表现 |
   |------|---------|
   | 全部完成（done） | 整圈实色（青绿，沿用 `--color-priority-low`）+ 数字旁小 ✓ |
   | 部分完成（partial） | 环按 `done/total` 比例填充（金色，沿用 `--personal-secondary`） |
   | 有任务全未完成（open） | 空心环（灰，`#a1a1aa`） |
   | 有高优先级未完成（urgent） | 在上述基础上环描红（`--color-priority-high`），保留紧急提示 |
   | 无任务（none） | 不画环 |

   实现方式：优先 CSS `conic-gradient` 按百分比填充（无新增依赖），进度百分比通过 CSS 变量传入（如 `--progress: 60%`）；或 SVG 圆环。

3. **悬停提示**：`title` 从"有任务状态"改为真实文案，如「已完成 3 / 共 5」。

### 验收
- 满环 + ✓ 一眼可辨"这天做完了"。
- 部分完成的天能看出大致比例。
- 悬停显示具体 `已完成/总数`。
- 减少动画偏好（prefers-reduced-motion）下环形直接呈现，不做填充动画。

## A4. 追加记录：空字段不写入 Obsidian

### 现状
`shared/appSettings.ts:55-60` 的 `completionReviewTemplate` 固定 4 行；`shared/obsidianTemplates.ts:112-124` 的 `buildTaskLines()` 渲染时，空字段经 `escapeReviewText`（`obsidianTemplates.ts:57-59`）被转成 `'-'`，整行照样写入。

用户只填"下一步"时，Obsidian 实际写入：
```
- 阶段记录 1：部分完成，完成度 80%，记录时间 ...
  - 今天情况：-
  - 还没懂/卡点：-
  - 下一步：明天先复盘
```

### 方案
改 `shared/obsidianTemplates.ts` 的 `buildTaskLines()`，对一条阶段记录分两部分生成：

- **首行（必写）**：阶段记录序号 / 状态 / 完成度 / 记录时间——保持现状。
- **明细行（逐行判空）**：`今天情况` / `还没懂卡点` / `下一步` 三行，**对原始值 trim 后为空则整行跳过**，非空才渲染。

期望输出（只填下一步）：
```
- 阶段记录 1：部分完成，完成度 80%，记录时间 ...
  - 下一步：明天先复盘
```

### 边界
- 判空基于**原始 review 字段值 trim** 后是否为空，而非渲染后的 `'-'`。
- 三个明细字段全空时，只保留首行。
- 不改首行字段（状态/完成度/时间恒有值）。
- `escapeReviewText` 的"空转 `-`"兜底对仍要渲染的字段保留；被判空跳过的行不再触发它。

### 验收
- 只填某一个明细字段时，Obsidian 只写该字段行。
- 三个都填则三行都在。
- 都不填则只剩首行。
- 现有已写入文件不受影响（仅影响新写入）。

## A5. 任务列表方向键操作

### 现状
方向键（ArrowUp/Down）目前仅在 `DailyWorkPanel` 的 `/` 命令菜单内生效（`DailyWorkPanel.tsx:198-206`）。任务列表（`TaskList.tsx` / `TaskItem.tsx`）**无键盘导航**。任务数据模型（`types/task.ts`）含 `completed` / `priority` 等字段，操作函数（toggle、改优先级、删除、编辑）已存在。

### 方案
给任务列表引入**键盘选中态**与操作（用户确认全部勾选）：

新增 UI 状态 `selectedTaskId`（提升到 App 或 TaskList 层）。当任务列表区域获得焦点时接管方向键：

| 键 | 操作 |
|----|------|
| ↑ / ↓ | 在可见任务间移动选中项（高亮当前项） |
| ← / → 或 1 / 2 / 3 | 改优先级 高 / 中 / 低 |
| 空格 | 勾选 / 取消完成 |
| Enter 或 e | 进入该任务编辑 |
| Delete | 删除该任务（沿用现有删除确认流程） |
| Esc | 取消选中 |

### 边界与冲突处理
- **焦点隔离**：只有任务列表容器持有焦点时才接管方向键，避免与编辑框、日历方向键冲突。容器设 `tabIndex` 使其可聚焦。
- **与拖拽排序共存**：现有 dnd-kit 排序保留；键盘选中态是独立的视觉/交互层，不触发拖拽。
- **进入编辑时让出键盘**：Enter/e 进入编辑后，方向键归编辑框，列表暂停接管，退出编辑恢复。
- **删除复用现有确认**：不新造删除逻辑，调用现有删除入口（含确认/撤销，若现状有）。
- **可见集一致**：方向键移动只在当前 Tab/筛选后的可见任务集内循环。
- **切换后清空选中**：切换 Tab / 筛选 / 日期后，选中态清空（取最不意外的行为）。
- **无障碍**：选中项加 `aria-selected`；提供可见的选中高亮（不仅靠颜色）。

### 验收
- 列表聚焦后可用 ↑↓ 移动选中、改优先级、勾选、进入编辑、删除。
- 与鼠标点击、拖拽排序、编辑框输入无相互干扰。

## A6. 「完成」Tab 改为复盘 / 历史视图

### 现状
`TabBar.tsx:9-13` 定义三个 Tab：当天 / 全部 / 完成。`completed` 的筛选逻辑（`useTasks.ts:389-390`）为 `taskDate === selectedDate && task.completed`——**只列当天打勾的任务**，且**完全没用上** `task.completionReviews`（每条含 `今天情况/卡点/下一步/完成度% + reviewedAt`，支持一个任务多次记录）。用户反馈"存在感低、用不到"。

### 方案
把该 Tab 从"当天已完成清单"重做为**复盘视图**：

- **范围跨日期**：不再限 `selectedDate`，展示所有完成过的任务。
- **按时间倒序**：以 `completedAt`（或最近一条 `completionReviews[].reviewedAt`）排序。
- **按日期分组**：今天 / 昨天 / 更早，形成时间线。
- **展开看记录**：每条可展开查看当时写的 `下一步 / 心得(今天情况) / 卡点 / 完成度%`，数据直接读 `completionReviews` 数组（无需新数据）。
- **命名**：Tab 文案由「完成」改为「复盘」（或「回顾」）。

### 边界
- 数据全部来自现有模型，无需迁移。
- 一个任务有多条 `completionReviews` 时，复盘视图按记录条目展示（而非仅任务），使时间线连贯。
- `cleared` 的任务：仍展示其历史记录（复盘价值不应因清理列表而消失）——除非实现中发现 cleared 语义冲突，则回报再定。
- 空状态：无任何完成记录时显示友好空态（"还没有复盘记录"+引导），不留空白。

### 验收
- 切到该 Tab 能看到跨日期、按时间倒序、分组的完成记录。
- 展开能看到追加记录里写的内容，与写入 Obsidian 的内容一致。
- 空态友好。

## 跨改动的统一约束

- **不破坏现有验证脚本**：项目有 `npm run verify:*` 系列（见 `package.json`），改动后需保证相关 verify 仍通过；涉及编辑器/追加记录的改动尤其要跑 `verify:markdown-editor`、`verify:daily-command`、`verify:delete-review`。
- **无障碍**（技能 CRITICAL 优先级）：方向键导航、选中态、环形进度均需满足对比度、`aria-*`、不仅靠颜色传达信息、尊重 reduced-motion。
- **UTF-8 / 中文**：所有写入 UTF-8；保留中文文案。
- **最小改动**：不顺手重构无关代码；A1 的抽 Hook 是为本批改动服务的必要重构，不扩大化。
