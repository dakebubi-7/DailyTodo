# DailyTodo 产品优化设计说明

日期：2026-07-03

## 目标

这份文档的目标，是把 DailyTodo 从“一个好看的待办应用”，重新定位成一个更清楚、更有商业价值的产品：

> **面向独立开发者的本地优先 AI 每日执行力教练。**

更直白地说：

> DailyTodo 不只是帮用户记录任务，而是帮用户每天从一堆任务里选出真正该推进的 1-3 件事，拆成能马上开始的下一步，并在晚上自动形成复盘。

这个方向可以让 DailyTodo 避开普通待办软件的红海竞争，也更容易做出自己的价值。

## 背景

之前的讨论是从这个问题开始的：

> 我的这个应用现在市面上有重复性吗？有商业价值吗？

结论是：

- 如果 DailyTodo 只是普通待办、日程、任务列表，那么重复度很高。
- 市面上已经有 TickTick / 滴答清单、Todoist、Microsoft To Do、Things、Notion Calendar、飞书日历、Motion、Akiflow、Sunsama、Reclaim.ai 等很多竞品。
- 如果只做“更好看的 Todo + AI 总结”，商业价值不够强。
- DailyTodo 更适合走一个更窄、更清楚的方向：服务独立开发者的每日执行闭环。

同时，DailyTodo 不应该去做：

- 团队日历
- 企业协同
- 会议室管理
- 同事忙闲状态
- 企业排期
- 大型项目管理

这些方向已经被飞书、钉钉、Notion、Google Calendar、Microsoft 这类产品占据，不适合作为 DailyTodo 的突破口。

## 范围

这份文档主要说明产品方向，不是代码实现方案。

包含：

- 产品定位
- 目标用户
- 核心使用闭环
- 首页和任务区的信息架构
- “今日重点”系统
- AI 应该怎么介入
- 功能优先级
- 免费版和 Pro 版边界
- 商业化建议
- 接下来 1-2 个月路线图

不包含：

- 具体代码怎么改
- 数据库结构怎么改
- License 激活怎么做
- 付款系统怎么接
- 具体 AI prompt 怎么写
- 具体 UI 颜色、阴影、玻璃效果怎么调

## 产品定位

DailyTodo 建议定位为：

> **面向独立开发者的本地优先 AI 每日执行力教练。**

也可以更口语化地表达为：

> 每天帮你选出真正该推进的 1-3 件事，拆成能开始的一小步，并在结束时自动复盘沉淀。

这个定位有几个关键点：

1. **面向独立开发者**  
   不服务所有人，先服务一个更明确的人群。

2. **本地优先**  
   利用 Electron 桌面应用、本地文件、本地数据、Obsidian 友好、用户自带 API Key 这些优势。

3. **AI 每日执行力教练**  
   AI 不是为了炫技，而是帮助用户减少纠结、降低任务启动阻力、形成复盘。

4. **每日闭环**  
   不是一次性任务管理，而是每天打开、每天推进、每天沉淀。

## 目标用户

第一阶段建议服务：

> 有多个项目、经常上下文切换、每天任务很多，但最痛苦的是“不知道今天到底先做什么”的独立开发者。

这类用户通常有这些特点：

- 有 side project、客户项目、bug、学习任务、文档、发布、运营等很多事情。
- 打开任务列表时，不是没有任务，而是任务太多。
- 经常在“修小 bug”“调 UI”“看资料”“整理配置”“写文档”之间来回切换。
- 想记录今天做了什么，但不想每天手写日报或周报。
- 更偏好本地数据、文件导出、Obsidian、Markdown。
- 愿意自带 AI API Key。
- 比普通用户更可能为一个真正有用的开发者工具买断付费。

这类人需要的不是一个更大的任务列表，而是一个更清楚的：

> 今日推进判断器。

## 产品核心原则

以后每加一个功能，都先问一句：

> 这个功能能不能帮助用户更快开始、持续推进、顺利复盘今天最重要的任务？

如果答案是否定的，就不应该优先做，至少不应该放在首页主位置。

## 核心闭环

DailyTodo 的核心闭环建议定义为：

> **选重点 → 拆下一步 → 推进任务 → 自动复盘 → 生成明日建议**

每天主要帮助用户回答 5 个问题：

1. 今天最该做什么？
2. 为什么是这些事？
3. 下一步具体怎么开始？
4. 今天实际推进了什么？
5. 明天应该怎么调整？

这 5 个问题比“添加任务”“筛选任务”“完成任务”更重要。

普通 Todo 的核心是：

> 把任务记下来。

DailyTodo 应该变成：

> 帮用户每天真正推进关键任务。

## 首页信息架构

首页不应该只是一个任务列表，而应该变成：

> **今日执行首页。**

建议首页从上到下分成 4 层。

### 第一层：今日导航层

这一层回答：

- 今天是哪一天？
- 今天整体状态如何？

可以包含：

- 日期 / 星期
- 今日完成度
- 今日重点数量
- 一个简短状态提示

例如：

- 今天有 2 个重点任务。
- 昨天有 1 个高优先任务没有完成。
- 建议先推进“修复任务栈视觉层级”。

这一层不要太重，不要做成复杂 dashboard。它只是帮助用户进入今天。

### 第二层：今日重点层

这是首页最重要的一层，应该成为视觉中心。

建议显示：

- 今日 1-3 个重点任务
- 每个重点任务的原因
- 每个重点任务的下一步
- 当前状态：未开始 / 进行中 / 阻塞 / 已完成

普通 Todo 是“列出所有事情”。

DailyTodo 应该是：

> 先帮用户确定今天最值得推进的少数几件事。

### 第三层：任务执行层

这里是普通任务列表，但不要再是一个平铺的长列表。

可以按执行状态分组：

- 正在推进
- 待安排
- 阻塞 / 搁置
- 已完成

或者更简单一点：

- 今日重点
- 其他今日任务
- 已完成

这样任务列表本身也在服务执行，而不是只服务存储。

### 第四层：复盘与建议层

这一层可以放在底部，或默认折叠。

可以包含：

- 昨日复盘摘要
- 今日 AI 建议
- 明日预备事项
- 周报/月报入口

这一层不能抢走今日重点的注意力。它是辅助思考层，不是首页主角。

## 今日重点系统

“今日重点”应该成为 DailyTodo 的核心功能。

规则建议：

- 每天最多 1-3 个重点任务。
- 每个重点任务都应该有“为什么重要”。
- 每个重点任务都应该有“下一步”。
- 下一步最好是 5-20 分钟内可以开始的动作。
- 用户可以把普通任务提升为今日重点。
- 用户可以把今日重点降级为普通任务。
- 用户可以调整今日重点顺序。
- 没完成的今日重点可以带着上下文转到明天。
- AI 可以建议重点，但不能替用户强制决定。

例如，不要只是显示：

> 重构设置页

而应该显示：

> 重构设置页  
> 原因：它影响下一轮发布前的体验稳定性。  
> 下一步：先检查 4 个设置区块是否都能独立保存。

这个设计的关键是：

> 降低启动阻力。

用户不是不知道任务是什么，而是不知道怎么开始。

## 任务卡片层级

任务卡片应该有不同角色。

### 重点任务卡

重点任务卡应该最清晰。

应该显示：

- 任务标题
- 当前状态
- 为什么今天重要
- 下一步
- 轻量 AI 操作入口，例如“帮我拆下一步”

它不一定要很花哨，但一定要比普通任务更确定、更有主次。

### 普通任务卡

普通任务卡应该更轻。

它们依然要好读、好编辑，但不要和重点任务抢注意力。

很多操作可以在 hover 或选中时再显示。

### 折叠子任务 / 任务视觉栈

你现在项目里已经在做任务堆叠、折叠子任务、视觉层级。

这个方向不只是为了好看，也可以承担产品含义：

> 这个任务背后有复杂内容，但现在先被收纳起来，不打断当前执行。

也就是说，视觉栈可以表达“复杂任务已折叠管理”，帮助用户减少认知负担。

## AI 介入策略

AI 应该是：

> **执行辅助教练，不是任务主宰者。**

AI 应该帮助用户：

- 选今日重点
- 解释为什么这些任务重要
- 把大任务拆成下一步
- 识别任务是否太大、太模糊、被阻塞
- 根据剩余时间压缩计划
- 生成晚间短复盘
- 生成明日建议
- 从每日记录生成周报/月报

AI 不应该：

- 一直打扰用户
- 默认频繁重排所有任务
- 到处弹出建议
- 把首页变成聊天窗口
- 不经确认就替用户做决定
- 输出长篇大论的分析卡
- 变成通用项目经理或企业排期工具

默认体验应该是轻辅助。

以后可以在设置里提供更主动的模式，但一开始不要让用户觉得被 AI 管着。

## AI 出现的形式

AI 不建议做成一个到处都在的聊天框。

更适合这 3 种形式。

### 形式 1：嵌入式短建议

例如：

- 建议下一步：先跑验证脚本确认现状。
- 建议降级：这个任务今天不一定要做。
- 建议拆分：这个任务范围太大。

### 形式 2：一键动作

例如：

- 帮我拆下一步
- 建议今日重点
- 帮我写今日复盘
- 生成明天计划

### 形式 3：周期性总结卡

例如：

- 今日复盘
- 本周模式
- 本月推进概览

这些内容可以保存成本地记录，也可以导出到 Markdown 或 Obsidian。

## 功能优先级

### P1：最优先做

这些决定 DailyTodo 能不能成为“执行力教练”。

- 今日重点系统
- 重点任务原因
- 重点任务下一步
- 普通任务提升为今日重点
- 今日重点降级
- 今日重点排序
- 任务执行状态分组
- 晚间短复盘
- 明日建议草稿
- 本地优先数据流
- 用户自带 API Key 基础能力

### P2：后面增强

这些可以提高留存和产品质感，但应该等核心闭环更清楚后再做。

- 正在推进 / 待安排 / 阻塞 / 已完成等任务状态层
- 周报 / 月报从真实每日记录生成
- 任务聚类和视觉栈
- 桌面挂件或常驻入口
- Obsidian 友好导出
- Markdown 复盘记录

### P3：暂时不要优先做

这些不是没价值，而是现在容易让产品失焦。

- 完整模板市场
- 大型统计 dashboard
- 太多外部任务来源集成
- 团队协作
- 共享日历
- 会议排期
- 完整项目管理替代品
- 移动端
- 大型 AI 聊天工作区

## 商业化方向

DailyTodo 不适合直接靠“待办功能”收费。

因为普通待办功能已经太多免费竞品。

更适合收费的是：

> 帮用户节省规划时间、降低启动阻力、自动沉淀复盘。

推荐第一阶段商业模式：

> **买断 Pro + 用户自带 API Key。**

原因：

1. 独立开发者更容易接受买断工具。
2. 用户自带 API Key 可以避免你承担 AI 成本。
3. 本地优先定位更清楚。
4. 不需要一开始搭复杂 SaaS 后台。
5. 更适合个人开发者先发布验证。

建议定价：

- 海外早鸟：$19
- 海外 Pro 买断：$29-49
- 国内早鸟：¥69-99
- 国内正式买断：¥129-199

以后如果提供托管 AI、云同步、多设备同步，再考虑订阅。

## 免费版和 Pro 版边界

免费版不能锁太死，否则用户还没感受到价值就离开了。

### 免费版应该保留

- 添加 / 编辑 / 完成任务
- 今日任务列表
- 手动选择今日重点
- 基础任务分组
- 本地存储
- 基础主题
- 手动写每日复盘
- 简单导出

免费版要让用户体验到 DailyTodo 的基本方法论。

### Pro 版可以包含

- AI 今日重点建议
- AI 生成重点原因
- AI 拆下一步
- AI 识别阻塞任务 / 过大任务
- AI 晚间复盘
- AI 明日建议
- 从每日记录生成周报/月报
- 高级 Markdown / Obsidian 导出
- 高级复盘模板
- 高级主题或桌面挂件模式

注意：

> Pro 应该让核心闭环更省力、更智能，而不是让免费版完全不能用。

## 接下来 1-2 个月路线图

### 第一阶段：重构首页主线

目标：

> 首页从任务列表，变成今日执行首页。

优先做：

- 今日状态摘要
- 今日重点区域
- 重点任务视觉层级
- 其他任务降权
- 已完成任务折叠或弱化
- 搜索 / 筛选 / 标签降权

验收标准：

- 用户打开 5 秒内知道今天最重要的任务是什么。
- 首页第一屏不是一堆任务。
- 普通任务管理还可用，但不是视觉主角。

### 第二阶段：今日重点系统

目标：

> 用户不用 AI，也能每天明确 1-3 个重点任务。

优先做：

- 普通任务提升为今日重点
- 今日重点降级
- 今日重点排序
- 今日重点状态：未开始 / 进行中 / 阻塞 / 完成
- 下一步字段
- 为什么重要字段

验收标准：

- 每个重点任务都可以有下一步。
- 用户可以手动完成今日重点规划。
- 产品引导重点数量保持在 1-3 个。

### 第三阶段：低打扰 AI 辅助

目标：

> AI 只在关键时刻帮忙。

优先做：

- AI 推荐今日重点
- AI 生成重点原因
- AI 拆下一步
- AI 识别任务过大 / 被阻塞
- AI 生成晚间短复盘
- AI 生成明日建议

验收标准：

- AI 输出短、准、能行动。
- 用户可以接受、拒绝、编辑 AI 建议。
- 没有 API Key 时，产品仍然能作为手动本地工具使用。

### 第四阶段：复盘资产和 Pro 边界

目标：

> 让每日执行记录积累成长期价值。

优先做：

- 每日重点和复盘保存成本地记录
- 周报/月报从每日记录生成
- 加强 Markdown / Obsidian 导出
- 显示 Pro 功能边界，但不要太打扰
- 打磨 BYOK 设置

验收标准：

- 用户可以回看一周内每天的重点和结果。
- 周报/月报不是凭空生成，而是来自真实每日记录。
- Pro 可以解释为“帮你节省规划和复盘时间”。

## 不应该做什么

短期不要做：

- 团队日历
- 会议排期
- 多人协作
- 企业项目管理
- 大型统计中心
- 完整 Notion 替代品
- 通用 AI 聊天助手
- 过早移动端
- 过早云同步
- 复杂模板市场

这些能力会让 DailyTodo 失去主线。

当前最重要的是证明：

> 独立开发者每天打开 DailyTodo 后，真的更容易开始和完成关键任务。

## 风险

### 风险 1：首页变成功能门户

如果把报表、模板、设置、AI 面板、统计卡都放首页，首页就会失去“今日执行”主线。

解决方式：

> 首页只服务今天。

### 风险 2：AI 太吵

如果每个区域都有 AI 建议，用户很快会麻木，甚至讨厌 AI。

解决方式：

> AI 只在开始、卡住、复盘、周/月总结这些关键时刻出现。

### 风险 3：还没验证闭环就做太多扩展

如果今日重点还不好用，就去做集成、模板、统计、商业化，会分散精力。

解决方式：

> 先验证“选重点 → 拆下一步 → 复盘”闭环。

### 风险 4：免费版锁太死

如果用户还没体验到价值就遇到付费墙，会很难转化。

解决方式：

> 手动今日重点和手动复盘免费，AI 加速和长期复盘资产做 Pro。

### 风险 5：丢掉本地优先信任

如果 AI 和 Pro 让产品看起来像云端 SaaS，会削弱本地优先优势。

解决方式：

> 持续强调本地存储、导出、BYOK、不强制云。

## 成功指标

### 使用指标

- 用户是否每天打开应用
- 每天是否选择 1-3 个今日重点
- 今日重点完成率
- 有多少重点任务写了下一步
- 有多少阻塞任务被解决或降级

### 复盘指标

- 每日复盘生成率
- 连续复盘天数
- 周报/月报是否来自真实每日记录
- Markdown / Obsidian 导出使用情况

### AI 价值指标

- AI 今日重点建议是否被接受或编辑
- AI 下一步建议是否被接受或编辑
- AI 复盘草稿是否被保存
- 用户是否愿意配置自己的 API Key

### 商业指标

- 用户是否对 Pro 功能感兴趣
- 早鸟买断转化率
- BYOK 设置完成率
- 用户是否愿意推荐给其他独立开发者

## 后续实施建议

后续如果要进入实现计划，建议拆成这些部分：

1. 今日重点数据结构
2. 首页层级调整
3. 任务卡片角色区分
4. 手动今日重点管理交互
5. AI 建议入口和边界
6. 每日复盘保存与导出
7. Pro / BYOK 设置展示

第一步应该先做：

> **手动今日重点系统。**

原因是：

> AI 只有在产品已经有清楚的“今日重点”目标之后，才有真正发挥空间。

不要一上来先做 AI。先让手动闭环成立，再让 AI 帮它变得更省力。
