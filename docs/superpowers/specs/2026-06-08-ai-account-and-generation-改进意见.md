# DailyTodo · AI 账号与生成体验 — 修改意见

> 日期：2026-06-08
> 背景：在已实现的"轻量多账号(A-lite)"基础上，用户反馈 5 点。本文是改进意见（不含代码），用于先对齐方向，再决定实施顺序。

---

## 一、生成内容有时不完整（用户反馈 1）

### 现象
日复盘 / 周报 / 月报有时只生成一半或明显被截断。

### 原因分析（按可能性从高到低）
1. **Anthropic 输出被硬编码截断**：`openaiClient.ts` 里 `DEFAULT_MAX_TOKENS = 4096`，且只在 Anthropic 协议下传 `max_tokens`。长月报很容易超过 4096 token 被截。
2. **OpenAI / Gemini 没设输出上限**：走模型默认值，通常够用，但部分中转站默认上限很低，也会截断。
3. **请求超时中断**：`timeoutSeconds` 到点就 abort，长内容生成时会得到半截或空结果。
4. **没有流式输出**：一次性等全部返回，响应越长越容易撞上超时。
5. **输入过大挤占输出预算**：周/月报会把多天 daily 正文拼进 prompt，输入太大时模型剩给输出的额度变少，或触发上下文上限。

### 建议
- 把 `max_tokens` 提为**可配置**（账号级或全局），默认调高（如 8192）。
- 三种协议（OpenAI / Anthropic / Gemini）**统一传输出上限**参数。
- 加**截断检测**：当返回 `finish_reason = length`（或 Anthropic `stop_reason = max_tokens`）时，给用户明确提示，或自动"续写"补全。
- 可选引入**流式**，并把超时改成"一段时间无新增内容才超时"。
- 报告输入做**摘要 / 长度保护**，避免输入吃满预算。

### 优先级：**高**（直接影响可用性）

## 二、模板识别支持"选文件"而不是"粘贴"（用户反馈 2）

### 现状
"认我的模板 / 认报告格式"只能手动粘贴文本。

### 建议
增加"选择文件识别"：
- 用 Electron `dialog.showOpenDialog`，过滤 `.md / .txt / .docx / .pdf`（`.doc` 老格式见下）。
- 文件 → 纯文本解析后，**复用现有** `recognizeTemplate / recognizeReportTemplate` 流程：
  - `.md / .txt`：直接读取。
  - `.docx`：建议用 `mammoth`（提取纯文本，体积小）。
  - `.pdf`：用 `pdf-parse` 或 `pdfjs`（注意扫描件无文字层时提取为空，需提示）。
  - `.doc`（旧二进制）：解析麻烦，建议提示用户"另存为 .docx"，不单独支持。
- 处理好失败兜底：解析为空 / 超大文件 / 加密 PDF 都要有清晰提示。

### 复杂度：**中**（要引入解析依赖、处理各种异常）
### 优先级：**中**

## 三、新增账号后，之前的账号没被保存（用户反馈 3）— Bug

### 诊断：确认是真实 Bug（我引入的）
根因在 `SettingsPanel.tsx`：
- 表单每个输入框**每次按键**都会 `updateActiveProfile → patchSettings`，而 `patchSettings` 同时做了 `setSettings(next)` **和**一个异步的 `setSettings(saved)` 回写。
- 多个异步保存各自捕获的是**旧的 `settings` 闭包**，后返回的那个会**覆盖**先返回的状态（竞态）。在"快速编辑 → 立刻点新增"时，晚到的回写会把刚加/刚改的账号数据冲掉。
- 同时 UI **没有账号列表**，切到新账号后看不到旧账号，加重了"丢了"的错觉。

### 建议修复
- 状态更新改为**函数式** `setSettings(prev => ...)`，消除闭包竞态。
- **本地状态为准**：保存改为 fire-and-forget（或防抖），不要用 IPC 返回值粗暴覆盖整个 state。
- 配合第五点显示账号列表，让"已保存的账号"始终可见。

### 优先级：**最高**（涉及数据丢失）

## 四、设置界面太长，需要压缩（用户反馈 4）

### 建议
设置页 → AI 复盘 改成**分区折叠（accordion）**：
- 区块：`账号` / `定时生成` / `报告路径` / `报告模板` / `复盘段落`。
- 默认只展开 `账号`，其余收起。
- 每个区块是一张可点开/收起的卡片。

### 复杂度：**低-中**（纯前端）
### 优先级：**中**（和第五点一起做最划算，都是设置页重构）

## 五、账号管理改造（用户反馈 5）— 核心诉求

### 目标：体验类似 CC Switch
- 顶部：`账号` + 下拉框（当前生效账号），旁边一个「管理」入口。
- 「管理」弹窗/抽屉：**账号列表**，每个账号是**独立的一整套设置**（名称 / 协议 / baseUrl / key / model / timeout / 备注 / 类型）。
- 列表里**显示余额**：按量 → 显示金额；订阅 → 显示剩余时间/额度。

### 余额显示的可行性（需要坦诚说明）
不同平台差异很大，**做不到全平台统一**：
- **DeepSeek**：有余额查询接口，可查。
- **中转站（OpenAI 兼容）**：很多实现了旧版 OpenAI 计费接口（`/dashboard/billing/subscription` + `/usage`），多数可查。
- **OpenAI 官方**：已无公开余额接口，查不到。
- **Anthropic 官方**：无公开余额接口，查不到。
- **订阅到期时间**：一般 API 查不到，需要手动填。

→ 方案：每个账号加「类型」（按量 / 订阅 / 未知）+ **best-effort 自动查询**（按 provider 尝试）+ **手动兜底字段**（手填余额/到期日）。查不到就显示"未知 / 手动"，不硬撑。

### 数据结构变化（`AiProfile`）
- 新增：`kind: 'credit' | 'subscription' | 'unknown'`
- 可选：`balanceEndpoint?`、手动余额 / 到期日、上次查询结果 + 查询时间（做缓存，避免频繁请求）
- 新增 IPC：`aiReview:queryBalance(profileId)`

### 复杂度：**高**
### 优先级：**高**（核心诉求），但建议**拆两步**：
1. 账号列表 + 管理界面（独立设置）— 必做、价值最大。
2. 余额查询 — 第二步增量，按平台逐个加。

## 建议实施顺序

| 顺序 | 内容 | 优先级 |
|------|------|--------|
| 1 | 修第三点竞态 Bug（防数据丢失） | P0 |
| 2 | 第五点第一步：账号列表 + 管理界面 + 第四点折叠（一起做，都是设置页重构） | P0 |
| 3 | 第一点：生成完整性（`max_tokens` 可配 + 截断检测） | P1 |
| 4 | 第五点第二步：余额查询（DeepSeek + 中转站 best-effort + 手动兜底） | P1 |
| 5 | 第二点：文件选择识别（.md/.txt/.docx/.pdf） | P2 |

## 风险 / 取舍
- 余额查询无法覆盖所有平台，要提前管理预期（OpenAI/Anthropic 官方查不到）。
- PDF/DOCX 解析会增加依赖体积，扫描版 PDF 无文字层会提取失败。
- 设置页重构时，要保证**已保存账号的迁移不丢**（和第三点一起验证）。
