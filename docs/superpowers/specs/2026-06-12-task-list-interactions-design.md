# DailyTodo 任务列表交互稳定性设计

## 背景

用户反馈任务列表存在三类高频问题：

1. 第一个任务的删除入口不稳定，有时点不到，有时又一直显示。
2. 列表偶发显示错位或视觉抖动。
3. 任务需要支持拖拽排序：默认个人任务在上、外部任务在下；大组可以拖换顺序；组内主任务默认按优先级排序，但当天可手动拖动固定顺序。

现有实现中，任务排序主要由 [useTasks.ts](../../../app/src/hooks/useTasks.ts) 依据完成状态和优先级动态排序；[TaskList.tsx](../../../app/src/components/TaskList.tsx) 按 `source` 分为个人任务和外部任务；[TaskItem.tsx](../../../app/src/components/TaskItem.tsx) 的删除按钮依赖 hover 显示。因此当前没有持久化的用户手动顺序，也存在 hover 命中区域不稳定的问题。

## 目标

- 支持当前日期内的大组拖拽排序。
- 支持当前日期内、同一大组内的主任务手动拖拽排序。
- 保持未拖拽日期的默认排序：个人任务在上、外部任务在下；组内主任务按优先级排序。
- 改善删除按钮命中稳定性，同时保持列表视觉简洁。
- 修复由 hover、动作按钮、展开/收起等造成的布局不稳定。

## 非目标

- 不支持子任务拖拽排序。
- 不支持跨组拖动主任务来改变任务来源。
- 不支持跨日期共享手动排序。
- 不重构完整任务存储模型，只新增当前功能需要的排序状态。

## 数据设计

新增按日期保存的任务列表排序状态。每个日期可包含：

- `sourceOrder`: 当前日期的大组顺序，默认 `['personal', 'external']`。
- `taskOrderBySource`: 当前日期各大组内的主任务顺序，例如 `{ personal: string[], external: string[] }`。

没有排序记录的日期不写入额外状态，继续使用默认逻辑。

排序优先级：

1. 完成状态仍优先分层：未完成任务显示在已完成任务前。
2. 若当前日期、当前大组存在手动顺序，则在同一完成状态内按手动顺序排列。
3. 不在手动顺序中的新任务按优先级插入到合理位置，不打乱已有手动顺序。
4. 没有手动顺序的大组继续按优先级排序。

这样保证拖拽只影响当天，并且不会让已完成任务挤占当前任务区域。

## 交互设计

### 大组拖拽

“个人任务”和“外部任务”的分组标题增加弱化的拖拽把手。拖动分组标题只改变当前日期的大组上下顺序。

默认顺序始终是：个人任务在上、外部任务在下。只有当天用户拖动过大组，才保存当天的大组顺序。

### 主任务拖拽

每条主任务增加弱化拖拽把手。拖拽仅在同一大组内生效，不改变任务来源。

未拖动过时，组内主任务按优先级排序。用户第一次拖动某个组内任务后，该日期该组进入手动排序模式；后续显示以手动顺序为准。

### 筛选状态

搜索、只看未完成、优先级筛选开启时禁用拖拽，并隐藏或弱化拖拽把手。原因是筛选后的列表不是完整排序上下文，允许拖拽会让结果难以预测。

### 子任务

子任务继续跟随父任务显示和折叠。当前设计不支持子任务拖拽，以避免父子层级、缩进和折叠状态相互冲突。

## 删除入口设计

删除按钮不常驻显示，保持列表简洁。

任务卡片右侧增加稳定的隐形热区：

- 鼠标进入任务卡片右侧热区时，删除按钮淡入显示。
- 删除按钮使用绝对定位浮在右侧，不参与任务文本布局。
- 任务文本区域保留右侧安全 padding，避免长标题被删除按钮覆盖。
- 删除按钮的可点击区域满足至少 44px 的触控/鼠标命中尺寸。
- 右键菜单继续保留删除入口，作为兜底。

这样既避免删除按钮一直可见，也避免依赖精确 hover 到小图标。

## 显示稳定性设计

任务行的交互状态不得改变外层布局尺寸。

- 删除按钮、复盘按钮、拖拽把手使用固定层级和绝对定位或固定安全空间。
- hover、按下、完成切换只改变透明度、颜色或轻微 transform，不改变卡片宽高。
- 分组标题、任务行、子任务行使用统一间距。
- 子任务展开/收起只影响当前父任务下方区域，不改变兄弟任务的内部结构。
- 长任务标题按现有布局换行或截断，不因动作按钮出现而重新挤压。

## 验证计划

- 新建个人任务和外部任务，确认默认显示为个人任务在上、外部任务在下。
- 拖动大组顺序，刷新或切换日期回来后确认当天顺序保持。
- 切换到其他日期，确认仍使用默认大组顺序。
- 在同一大组内拖动主任务，确认当天组内顺序保持。
- 新增任务后，确认新任务按优先级加入，不打乱已有手动顺序。
- 搜索、只看未完成、优先级筛选开启时确认拖拽不可用。
- 在第一条任务右侧移动鼠标，确认删除按钮稳定出现且可点击。
- 右键菜单删除任务仍可用。
- 检查任务行 hover、删除按钮出现、子任务展开/收起时没有横向错位或明显跳动。

## 实现边界

该设计只覆盖任务列表交互稳定性。完成弹窗设置、AI 复盘 token 显示、生成速度分析和 Obsidian 写入冲突将作为后续独立设计处理。
