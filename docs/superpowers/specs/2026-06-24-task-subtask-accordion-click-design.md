# 2026-06-24 主任务子任务展开改为卡片底座风琴设计

## 背景

当前主任务列表里，带子任务的主任务已经从“左侧小三角”改成了“点击主任务主体区域展开/收起”。但视觉上还没有做到你给的参考图那种效果：

- 主任务下面应该先看到一层很薄的“页/底座”
- 这层底座要**紧贴**主任务，不要离得太远
- 展开时，底座像被顶开一样让子任务从里面弹出来
- 展开后，底座不消失，而是保留一丝很淡的页边或阴影，作为底座

现有实现位置：

- `app/src/components/TaskItem.tsx`：主任务行结构、折叠触发、子任务渲染
- `app/src/hooks/useTasks.ts`：`toggleTaskCollapse` 和 `collapsed` 状态持久保存
- `app/src/types/task.ts`：`Task.collapsed` 字段定义
- `app/src/styles/globals.css`：任务卡、子任务、折叠底座样式
- `app/scripts/verify-ui-feedback-regressions.ts`：当前回归检查脚本

## 目标

- 让带子任务的主任务呈现成**参考图那种卡片底座风琴**。
- 收起时，主任务下方有一层很薄的“页/底座”可见。
- 展开时，底座像被打开，子任务从底座里滑出/弹出。
- 展开后，底座保留一丝很淡的页边或阴影，不要完全消失成普通列表。
- 保持主任务点击主体区域展开/收起的交互不变。
- 保持完成、优先级、删除、查看、拖拽等控件互不干扰。

## 非目标

- 不实现互斥式 accordion。
- 不改子任务数据结构。
- 不新增子任务嵌套能力。
- 不改子任务完成、删除、复盘等交互。
- 不把整个任务列表改成新的卡片系统。

## 视觉目标

参考图的关键不是“下面多一块空白”，而是“主卡片自带一层轻薄底座”。因此这个设计要满足三条：

1. **距离极近**
   底座必须和主卡片几乎贴住，只留很窄的过渡，不允许出现明显空洞。

2. **层次清晰**
   底座要在主卡片之下、下一条任务之上，形成清楚的层叠关系，而不是被后面的任务盖住。

3. **展开后仍保留底感**
   子任务出现以后，底座不是完全消失，而是保留一丝很淡的边缘/阴影，让它仍然像一个被打开的卡片底座。

## 交互设计

### 顶层主任务

- 点击带子任务的主任务主体区域，切换 `collapsed`。
- 再次点击同一区域，收起子任务。
- 点击拖拽、完成、优先级、查看/补写完成情况、删除等按钮，只执行各自动作，不触发展开/收起。

### 折叠态

- 主任务卡片下方显示一层薄薄的卡片底座。
- 底座要像“下面还有一页”，但不能厚重。
- 这层底座要和主任务一起构成一个整体，不要像独立列表项。

### 展开态

- 底座先有一个轻微的打开/撑开动作。
- 子任务从底座里滑出。
- 子任务出现后，底座保留极淡的页边或阴影，不能突然完全没掉。

## 结构设计

### 1. 主卡片层

主任务的主体行继续承担主要内容：

- 拖拽手柄
- 完成按钮
- 优先级按钮
- 标题文本
- 标签、日期等辅助信息
- 右侧查看/删除动作

这层始终是最显眼的顶部卡片。

### 2. 底座风琴层

在主卡片下方增加一层“页堆叠”视觉，作为卡片底座：

- 收起时可见
- 展开时轻微撑开
- 展开后只留下很淡的一层边缘/阴影

底座层的层次数可以根据直接子任务数量决定，但视觉上只显示 1-4 层的暗示，不要真的把每个子任务都画成完整页。

### 3. 子任务层

子任务仍然是真实的子任务列表，不变成伪造内容：

- 子任务展开时从底座里进入可视区域
- 子任务行继续保留自己的卡片样式和动作区
- 子任务层和底座层之间需要明确的 z-index 关系，避免被下一条主任务盖住

## 动画设计

### 收起到展开

建议按“两段式”理解：

1. 底座先被轻微顶开
2. 子任务再从底座里弹出

视觉上要像：

- 底座打开了
- 子任务是从这层底座里长出来的
- 最后底座仍留下一点薄薄的边缘感

### 展开到收起

反向执行：

1. 子任务先收回到底座
2. 底座再压回薄薄一层
3. 最后只剩主卡片下方那一丝轻阴影/页边

### 动画节奏

- 速度短、轻、顺滑
- 不要夸张翻页
- 不要做成明显的抽屉感
- 重点是“轻薄卡片底座被打开”的感觉

## 组件改动边界

### `TaskItem.tsx`

需要做的事情：

- 保留当前主任务主体点击展开/收起逻辑。
- 渲染主卡片下方的底座层，并根据 `collapsed` 状态切换展示。
- 子任务展开时从底座层中出现。
- 确保主任务动作区的按钮不会误触发展开/收起。
- 保持子任务层的现有交互与层级关系。

### `globals.css`

需要做的事情：

- 定义主卡片、底座层、子任务层之间的层级与间距。
- 控制底座层的薄边、阴影、圆角和透明度。
- 控制展开/收起时的过渡节奏。
- 确保底座层不会被下一条主任务盖住。
- 确保展开后仍保留一点极淡的页边/阴影作为底座。

### `app/scripts/verify-ui-feedback-regressions.ts`

需要补充/更新回归检查，确保：

- 主任务仍然渲染底座相关结构
- 底座层的样式类存在
- 展开后子任务容器仍然保留稳定 id
- 关键的视觉锚点没有被回退掉

### `useTasks.ts`

不修改折叠状态持久化，只复用现有 `collapsed` 逻辑。

## 风险与规避

### 风险 1：底座太远

如果底座离主任务太远，就会像下面多出一块空白，而不是卡片底座。

规避：

- 底座必须紧贴主卡片
- 不允许靠大间距制造层次
- 层次感靠阴影、透明度和轻微叠层实现

### 风险 2：底座被后面的任务盖住

如果底座的层叠关系处理不好，会出现你指出的“被下面盖住”问题。

规避：

- 底座必须明确处于当前任务节点的堆叠上下文里
- 必须保证它在视觉上盖住列表背景，但不挡住下一条任务的主卡片内容

### 风险 3：展开后看起来像重复卡片

如果底座和子任务都太厚，会像两层重复卡片。

规避：

- 展开后底座只保留一丝很淡的页边/阴影
- 子任务是主体，底座只是托底

### 风险 4：动作区误触发折叠

如果点击按钮区会冒泡到主体折叠，会破坏体验。

规避：

- 折叠触发范围只包住主体内容
- 动作按钮明确阻断冒泡或不在折叠热区内

## 验证计划

- 打开一个带子任务的主任务，确认收起态能看到紧贴主任务的薄底座。
- 点击主任务主体，确认子任务从底座中展开。
- 收起后，确认底座仍保留一丝很淡的页边/阴影。
- 点击完成、优先级、查看、删除、拖拽等按钮，确认不会触发展开/收起。
- 确认底座没有被下一条任务盖住。
- 运行 `npm --prefix app run verify:ui-feedback-regressions`。
- 运行 `npm --prefix app run typecheck`。

## 实现边界总结

这次不是普通的“展开列表”，而是一个**卡片底座风琴**：

- 主卡片在上
- 薄底座在下
- 展开时子任务从底座里弹出
- 收起时底座仍留一丝页边/阴影

目标是尽量贴近你给的参考图，而不是单纯把子任务往下堆。
