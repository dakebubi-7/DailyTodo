## 二、手动测试场景

### 场景 1: 首次启动向导 🎯 P0

**目标**：验证新用户零配置也能快速上手

**前置条件**：
- 清空配置文件（删除 electron-store 数据）
- 首次启动应用

**测试步骤**：
1. 启动应用 `npm run dev`
2. **验证**：首次向导自动弹出
3. 选择「使用默认模板」
4. 填写 API 配置：
   ```
   Base URL: https://api.deepseek.com/v1
   API Key: sk-xxxxxxxx
   Model: deepseek-chat
   ```
5. 设置时间：23:00
6. 点击「完成」

**预期结果**：
- ✅ 向导界面清晰易懂，无专业术语
- ✅ 配置保存成功
- ✅ 主界面正常显示
- ✅ 设置面板中可见已保存的配置

**失败标准**：
- ❌ 向导未弹出
- ❌ 配置保存失败
- ❌ 保存后设置丢失

### 场景 2: 日复盘自动生成（核心路径）🎯 P0

**目标**：验证同步后自动生成复盘

**前置条件**：
- 已配置 API Key
- Vault 路径已设置

**测试步骤**：
1. 创建 3 个任务：
   - "完成 AI 复盘测试"
   - "写测试文档"
   - "修复 bug"
2. 标记前 2 个为已完成
3. 在「今日工作」写一些内容
4. 点击「同步到 Obsidian」
5. 打开生成的 daily 文件：`logs/daily/2026-06-08.md`

**预期结果**：
- ✅ 文件包含三个标记块：
  ```markdown
  <!-- DAILYTODO:REVIEW:START -->
  <!-- DAILYTODO:AI_HASH:sha256:xxx -->
  🤖 AI 草稿
  ## 复盘
  [AI 生成的内容]
  <!-- DAILYTODO:REVIEW:END -->
  
  <!-- DAILYTODO:TOMORROW:START -->
  ## 明日待办
  - [ ] 修复 bug（结转）
  <!-- DAILYTODO:TOMORROW:END -->
  
  <!-- DAILYTODO:KNOWLEDGE:START -->
  ## 可复用知识
  [AI 生成的内容]
  <!-- DAILYTODO:KNOWLEDGE:END -->
  ```
- ✅ 复盘内容与当天任务相关
- ✅ 明日待办包含未完成任务
- ✅ 统计数字正确（完成 2/3）

**失败标准**：
- ❌ 标记块未生成
- ❌ 内容为空或报错
- ❌ 破坏了其他段落（任务、工作）

---

### 场景 3: 补偿扫描与漏填补齐 🎯 P0

**目标**：验证关机/错过也能自动补齐

**测试步骤**：

   ```markdown
   <!-- DAILYTODO:REVIEW:START -->
   <!-- DAILYTODO:REVIEW:END -->
   ```
2. 在设置面板点击「立即补偿扫描」（或重启应用）
3. 等待处理完成
4. 重新打开昨天的 daily 文件

**预期结果**：
- ✅ 复盘内容被自动补上
- ✅ 包含 AI_HASH 和 🤖 标识
- ✅ 内容与昨天的任务相关

**失败标准**：
- ❌ 内容未补上
- ❌ 报错或崩溃
- ❌ 补错了日期

### 场景 4: 用户修改保护（关键安全性）🎯 P0

**目标**：验证用户手动修改的内容不会被覆盖

**测试步骤**：
1. 打开今天的 daily 文件
2. 找到 AI 生成的复盘段落
3. 手动修改一些内容，如：
   ```markdown
   今天完成了测试工作。
   ↓ 改为
   今天完成了测试工作，还发现了两个值得注意的问题。
   ```
4. 保存文件
5. 回到应用，再次点击「同步到 Obsidian」
6. 再次打开 daily 文件

**预期结果**：
- ✅ 修改后的内容**完全保留**
- ✅ 没有被新的 AI 生成内容覆盖
- ✅ AI_HASH 行可能消失或变化（正常）

**失败标准**：
- ❌ 用户修改被覆盖（严重 bug）
- ❌ 文件损坏或格式错误

**失败标准**：
- ❌ 文件被破坏（部分写入、格式错乱）
- ❌ 应用崩溃
- ❌ 无错误提示或提示不清楚

**失败标准**：

## 四、边界测试

### 边界 1: 空数据
- 场景：没有任务、没有工作记录
- 预期：AI 生成「今天没有记录」提示，不崩溃

### 边界 2: 海量任务
- 场景：单日 100+ 任务
- 预期：正常生成，但可能需要更长时间

### 边界 3: 特殊字符
- 场景：任务标题包含 `<!-- -->` 、`[[]]` 等 Markdown 特殊语法
- 预期：正确处理，不破坏标记

### 边界 4: 非标准模板
- 场景：完全无法识别的模板
- 预期：降级到默认配置或追加到文件末尾，有提示

### 边界 5: 文件权限问题
- 场景：Vault 目录只读
- 预期：明确报错，不崩溃
